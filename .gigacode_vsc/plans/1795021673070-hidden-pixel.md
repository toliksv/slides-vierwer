# Plan: Iterative Correction Optimizer for SlidesViewer.FilmAnalyzer

## Goal
Implement an iterative closed-loop correction optimization system:
`[ROI Analysis] -> [Calculate Adjustments] -> [Virtual Apply on Preview] -> [Re-Analyze] -> [Damped Parameter Adjustment]` — until quality criteria are met or max iterations reached.

## Step 3: Create `IterativeCorrectionOptimizer` implementation

**File:** `SlidesViewer.FilmAnalyzer/Services/IterativeCorrectionOptimizer.cs`

### 3.1. Pre-processing (`PreparePreview`)
- Take the 16-bit `Mat` input.
- Detect and crop black border: scan 4 edges, find first non-black row/col. If no detection, crop 8% from each side.
- Resize to 800px on the long side (aspect ratio preserved).
- Convert from `CV_16UC3` to `CV_32FC3` with normalization to `0.0f .. 1.0f` range.

### 3.2. Virtual rendering pipeline (`ApplyVirtualAdjustments`)
Apply adjustments to `CV_32FC3` buffer **in Capture One engine order**:

| Step | Adjustment | Formula |
|------|-----------|---------|
| A | **Exposure** | `channel *= Math.Pow(2.0, exposureEV)` |
| B | **White Balance** (ColorTemperature + Tint) | Derive R/B multipliers from Δ(K − 5500) and Tint; apply to R and B channels. Negative Tint → boost G; Positive Tint → boost R & B. |
| C | **Highlight / Shadow** (Levels) | `val = (val − shadow) / (highlight − shadow)`, clamped to `[0.0f, 1.0f]` |
| D | **ColorBalanceMidtone** | Per-channel: `val *= (1 + (gain − 1) × 4 × val × (1 − val))` |
| E | **Tone Curves** (GradationCurve + per-channel Red/Green/Blue Points) | Build 4096-entry float LUT per channel with piecewise-linear interpolation; enforce strict monotonicity (`Y[i] ≥ Y[i−1]`); apply LUT to buffer |

**Important:** Steps D and E must handle per-channel gains and curves independently. The `ToneCurveAdjustment` points arrays are in 16-bit format `(X0, Y0, X1, Y1, …)` — normalize X/Y to `[0, 1]` range for LUT construction.

### 3.3. Metrics evaluation (`EvaluateMetrics`)
Compute on the post-adjustment `CV_32FC3` buffer:

| Metric | Definition | Target |
|--------|-----------|--------|
| `R_ClipHigh` | Fraction of pixels > 0.99f in R channel | ≤ 0.005 |
| `G_ClipHigh` | Fraction of pixels > 0.99f in G channel | ≤ 0.005 |
| `B_ClipHigh` | Fraction of pixels > 0.99f in B channel | ≤ 0.005 |
| `R_ClipLow` | Fraction of pixels < 0.005f in R channel | ≤ 0.01 |
| `G_ClipLow` | Fraction of pixels < 0.005f in G channel | ≤ 0.01 |
| `B_ClipLow` | Fraction of pixels < 0.005f in B channel | ≤ 0.01 |
| `HighlightCast` | `max(P95_R, P95_G, P95_B) − min(P95_R, P95_G, P95_B)` | ≤ 0.035 |
| `MidtoneCast` | `max(|P50_R − mean|, \|P50_G − mean\|, \|P50_B − mean\|)` where mean = (P50_R+P50_G+P50_B)/3 | ≤ 0.07 |
| `DynamicRange` | `max(P98_R,P98_G,P98_B) − min(P02_R,P02_G,P02_B)` | Slide80s: 0.82..0.94; ColorNegative90s: 0.86..0.96 |

Percentile computation: scan channel data, sort or use histogram approximation for efficiency. For the 800px preview (~640K pixels), a simple sort per channel is acceptable.

### 3.4. PID-like correction logic (`ApplyCorrections`)
Proportional controller with `learningRate = 0.5` (damping factor):

| Condition | Action |
|-----------|--------|
| **All criteria met** | Log convergence, `break` loop |
| **ClipHigh > 0.005** in any channel | `Exposure.Exposure -= 0.15 × learningRate`; reduce midtone gain for that channel; reduce midtone Y in that channel's curve |
| **ClipLow > 0.01** | `Exposure.Exposure += 0.15 × learningRate` |
| **HighlightCast > 0.035** | Adjust `WhiteBalance.ColorTemperature` by ±150×learningRate K (suppress dominant P95 channel); adjust `Tint` by ±1.5×learningRate |
| **MidtoneCast > 0.07** | Adjust `MidtoneRedGain/GreenGain/BlueGain` for channels with `ClipHigh < 0.002` (never lift a channel near clipping); adjust curve mid Y(0.5) for same channels |

**Corridor constraints:**
- `ColorTemperature`: 5000..6000 K (slides)
- `Tint`: -5..+5 (slides)
- `MidtoneRedGain/GreenGain/BlueGain`: 0.94..1.06
- Curve mid Y: 0.47..0.53

### 3.5. Iteration loop
```
for (iteration = 0; iteration < MaxIterations (8); iteration++)
{
    1. Clone initialAdjustments into working adjustments
    2. ApplyVirtualAdjustments → preview buffer
    3. EvaluateMetrics → metrics
    4. Log iteration info (metrics + corrections applied)
    5. If all criteria met → break
    6. ApplyCorrections → modify working adjustments
}
return working adjustments
```

## Step 4: Integrate into `FilmScannerAnalyzer`

**File:** `SlidesViewer.FilmAnalyzer/FilmScannerAnalyzer.cs`

### 4.1. Add constructor dependency
```csharp
private readonly IIterativeCorrectionOptimizer _optimizer;

public FilmScannerAnalyzer(
    IColorDegradationAnalyzer colorAnalyzer,
    IPhysicalDefectAnalyzer physicalAnalyzer,
    IQualityAssessmentService qualityAssessment,
    ICaptureOneStyleGenerator styleGenerator,
    IIterativeCorrectionOptimizer? optimizer = null)  // optional for backward compat
{
    _colorAnalyzer = colorAnalyzer;
    _physicalAnalyzer = physicalAnalyzer;
    _qualityAssessment = qualityAssessment;
    _styleGenerator = styleGenerator;
    _optimizer = optimizer ?? throw new ArgumentNullException(nameof(optimizer));
}
```

### 4.2. Modify `Analyze()` method
After `result.Corrections = GenerateCorrections(result);`, add:
```csharp
// Step 5: Iterative optimization (if optimizer is provided)
if (_optimizer != null)
{
    using var image = Cv2.ImRead(filePath, ImreadModes.Color | ImreadModes.AnyDepth);
    result.OptimizationLog = new();
    result.Corrections = _optimizer.Optimize(
        image,
        result.Corrections,
        result.Color.MediumType,
        out var log);
    result.OptimizationLog.AddRange(log);
}
```

Backward compatibility: if tests construct `FilmScannerAnalyzer` without the optimizer parameter (via existing 4-param constructor), optimization is skipped — no behavior change for existing callers.

## Risk Assessment & Mitigations

1. **Performance**: 800px preview + 8 iterations × full virtual pipeline ≈ fast (< 1 sec per slide). No risk.
2. **OpenCvSharp API**: Using only standard operations (`Resize`, `ConvertScale`, `CvtColor`, `Split`, `Merge`) — all well-documented.
3. **Backward compatibility**: Optional constructor parameter ensures existing tests pass without modification.
4. **Monotonicity enforcement**: Strict `Y[i] >= Y[i-1]` check prevents solarization — critical safety measure.
5. **No test breakage**: `SlidesViewer.Host.Tests` references only `SlidesViewer.Host`, not `FilmAnalyzer` directly. The optional parameter in the constructor ensures no compile errors.
